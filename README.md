Case de portifólio - Analista de Resquisitos

Visão Geral
Este projeto consiste na análise e especificação de requisitos para um sistema de automação de pedidos de uma MARMITARIA, atualmente atendendo exclusivamente via whatsapp, sem padronização de pedidos e sem controle estruturado de dados.
O objetivo do case é demonstrar minha capacidade de:
- Entender o problema do negócio;
- Mapear usuários e processos;
- Definir requisitos funcionais e não funcionais;
- Documentar regras de negócio e fluxos;

Observação: Projeto fictício com base em um cenário real, desenvolvido para fins de estudo e portifólio.

Contexto do Problema
A marmitaria enfrenta os seguintes problemas:
- Atendimento manual via whatsapp;
- Falta de padronização dos pedidos;
- Ausência de histórico de clientes;
- Erros frequentes e retrabalho;
- Falta de controle de dados de uma maneira geral;

Obejtivo do Sistema
Criar um sistema capaz de:
- Padronizar o recebimento de pedidos;
- Automatizar parte do atendimento via whatsapp;
- Centralizar dados de clientes, pedidos e produtos;
- Oferecer controle operacional (vendas, entregas e estoque);
- Reduzir erros, retrabalho e riscos de fraude;

Publico Alvo / Usuários
- Cliente da marmitaria - Realiza os pedidos;
- Lojista - Gerencia pedidos, produtos, estoque e caixa;
- Atendente balcão - Lança os pedidos manuais;
- Atendente Virtual (whatsapp) - Automatiza o recebimento de pedidos;
- Entregador - Realiza as entregas e pode fazer recebimentos via maquina movel;

Canais de Acesso
- Whatsapp;
- App da loja (interno);
- Navegador;
- Sistema de pagamento externo (máquina móvel);

Requisitos Funcionais
- RF01 – O sistema deve permitir o cadastro de clientes;
- RF02 – O sistema deve permitir o cadastro de produtos;
- RF03 – O sistema deve permitir a criação e emissão de pedidos;
- RF04 – O sistema deve permitir a exclusão de pedidos conforme regras de negócio;
- RF05 – O sistema deve permitir o cadastro de opções de entrega;
- RF06 – O sistema deve gerar um resumo do pedido;
- RF07 – O sistema deve permitir pagamentos por meios eletrônicos;
- RF08 – O sistema deve gerar relatório de controle de vendas;
- RF09 – O sistema deve gerar relatório de controle de entregas;
- RF10 – O sistema deve gerar relatório de controle de estoque;

Requisitos Não Funcionais

- RNF01 – Interface simples e intuitiva.
- RNF02 – Acesso via navegador e aplicativo.
- RNF03 – O sistema deve apresentar bom desempenho, sem atrasos perceptíveis.

Regas de Negócio
RN01 - O pedido só pode ser preparado após validação do pagamento;
RN02 - O cardápio pode variar conforme dia da semana;
RN03 - A exclusão de pedidos deve respeitar o status do pedido;
RN04 - A janela de entrega deve ser respeitada, afim de evitar sobrecarga;
RN05 - O sistema deve alertar sobre possíveis inconsistências de pagamento;

FLuxo do Pedido
1 - Cliente inicia pedido via whatsapp;
2 - Atendente virtual coleta e valida informações;
3 - Pedido é registrado no sistema;
4 - Lojista avalia pedido, janela de entrega e forma de pagamento;
5 - Se forma de pagamento OK, confirma e prossegue. Senão, rejeita o pedido;
6 - Pedido entra na fila de produção;
7 - Entrega é realizada conforme janela definida;

Artefatos Produzidos
- Mapa de contexto do problema;
- Lista de requisitos funcionais e não funcionais;
- Regras de negócio;
- Fluxo de pedido;
- Documento de Requisitor v1;

Concluindo:
Este projeto demonstra minha capacidade de atuar como analista de requisitos, conectando necessidade de negócio com soluções tecnicas, estruturando informações e apoiando o desenvolvimento de sistema, de forma clara e organizada;
